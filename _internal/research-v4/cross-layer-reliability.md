**보호 능력의 정의 (ARM 원문 용어, T1)**
- **SED** = Single Error Detect. 워드 전체에 패리티 1비트. 워드 크기는 RAM별 protection granule에 따름. (arm_a78.txt L4695-4697)
- **Interleaved parity** = 워드의 짝수 비트에 패리티 1비트, 홀수 비트에 패리티 1비트. (arm_a78.txt L4698-4700)
- **SECDED** = Single Error Correct, Double Error Detect. (arm_a78.txt L4701-4702)

**오류 다중도별 동작 (T1, arm_a78.txt L4705-4718 / arm_n1.txt 동일 문단)**
- 임의 RAM의 **1비트 오류**: 코어는 계속 진행하며 기능적으로 정확함.
- **서로 다른 RAM** 또는 **동일 RAM의 서로 다른 protection granule** 내 다중 1비트 오류: 역시 기능적으로 정확함.
- **동일 granule 내 2비트 오류**:
  - SECDED RAM → 검출하여 보고(report) 또는 지연(defer). **dirty 데이터가 든 캐시라인이면 데이터 손실 가능**.
  - SED만 있는 RAM → **2비트 오류를 검출하지 못함. 데이터 오염 가능**.
- **동일 granule 내 3비트 이상**: RAM 종류와 오류 위치에 따라 검출될 수도, 안 될 수도 있음.
- 오류가 없을 때 캐시 보호 기능의 **성능 영향은 최소(minimal)**.

## 2. 구조·메커니즘 서술

### 2-1. SRAM — 왜 L1은 패리티이고 L2는 ECC인가 (ARM TRM 기반, T1)

ARM Cortex-A78 / Neoverse N1 두 TRM이 **완전히 동일한 설계 원칙**을 보여줍니다. 이 원칙은 "성능 계층이 곧 보호 계층을 결정한다"로 요약됩니다.

**(a) 명령 캐시 = 패리티 + 무효화**
L1 명령 캐시의 tag는 패리티 1비트, data는 SED(패리티)뿐입니다. 정정 능력이 없습니다. 대신 **오류가 검출되면 해당 라인을 무효화하고 하위 메모리에서 다시 fetch**합니다.
근거: 명령 캐시는 **read-only clean 데이터만** 담습니다. 원본이 하위 메모리에 반드시 존재하므로, 오류를 고칠 필요 없이 버리고 다시 읽으면 됩니다. **검출만 하면 복구는 공짜**입니다. 따라서 값비싼 ECC 대신 1비트 패리티로 충분합니다.

**(b) 데이터 캐시 = SECDED + inline 정정**
L1 데이터 캐시는 tag·data 모두 SECDED입니다. **32비트 데이터 + poison 1비트에 ECC 7비트**가 붙습니다 (A78·N1 동일).
근거: 데이터 캐시는 **dirty 라인(하위 메모리에 없는 유일본)**을 담습니다. 무효화하면 데이터가 사라집니다. 따라서 정정 능력이 반드시 필요합니다.
→ **핵심 명제: 보호 강도를 가르는 것은 "계층 깊이"가 아니라 "그 RAM이 유일본을 담는가"입니다.**

**(c) ECC 오버헤드의 크기**
- L1 데이터: 32비트 데이터당 ECC 7비트 → 데이터 대비 **약 21.9%**
- L2 데이터: 64비트 데이터당 ECC 8비트 → 데이터 대비 **12.5%**
보호 granule이 커질수록 ECC 오버헤드 비율이 떨어집니다. L1은 32비트 단위로 잘게 접근해야 해서 granule을 키울 수 없고, 그 대가로 오버헤드가 L2의 약 1.75배입니다. **"L1이 비싸다"는 말에는 면적뿐 아니라 이 ECC 오버헤드도 포함됩니다.**

**(d) 보호하지 않는 RAM이 있다**
A78 기준 L1 BTB, L1 GHB, L1 BIM, L1 PHT(prefetch history table), L2 victim, MMU replacement policy는 **보호 없음(None)** 입니다.
근거: 이들은 **예측·힌트 구조**로, 값이 틀려도 결과가 틀리지 않고 성능만 나빠집니다. "아키텍처적으로 가시적인 상태(architecturally visible state)"가 아닌 것은 보호하지 않는 것이 설계 원칙입니다.

**(e) poison bit**
L1 데이터 캐시 data RAM에 **poison 비트 1개**가 별도로 있습니다. 정정 불가 오류(2비트)를 만났을 때 즉시 머신 체크로 죽이는 대신, "이 데이터는 오염됐다"는 표식을 데이터와 함께 흘려보내는 **deferred error** 방식입니다. 실제로 그 값을 소비하는 소프트웨어에 도달했을 때만 오류를 발생시켜, **오류 격리 범위를 최소화**합니다. ARM 원문도 SECDED RAM의 2비트 오류를 "report or **defer**"라고 표현합니다.

**(f) 중간 단계 — interleaved parity**
MMU translation cache는 71비트 granule에 **짝수 비트용 패리티 1개 + 홀수 비트용 패리티 1개**를 씁니다. 물리적으로 인접한 셀에 동시에 발생하는 **MCU(multi-cell upset)** 는 인접 비트를 함께 뒤집는데, 비트를 인터리빙해 두면 인접 2비트 오류가 서로 다른 패리티 그룹에 떨어져 **둘 다 검출**됩니다. 단일 패리티는 짝수 개 오류를 놓치므로, 이는 ECC 없이 MCU 검출률을 올리는 저비용 기법입니다.

**(g) 보호는 granule 단위로 계산된다**
ARM이 반복 강조하는 것은 "서로 **다른 protection granule**에 있는 다중 1비트 오류는 전부 정정된다"는 점입니다. 즉 캐시 전체에 오류가 여러 개 있어도, **같은 granule 안에 2개가 겹치지 않는 한** 코어는 정상입니다. SER 계산에서 "칩 전체 오류율"이 아니라 "granule 내 오류 중첩 확률"을 봐야 하는 이유입니다.

### 2-2. SRAM — soft error의 물리 (seu.txt 기반, T2)

**단면적(cross-section) → FIT 변환 체인**
SER은 소자 고유값이 아니라 **환경 조건과의 곱**입니다.
1. **static cross-section** = 사건 수 / fluence [cm²]. 소자 고유 취약도.
2. **flux** = 단위 시간·면적당 입자 수. **NYC 해수면 기준 약 13 n/cm²·h**.
3. FIT = cross-section × flux × 10⁹시간.
4. MTTF[h] = 10⁹ / FIT.

**static vs dynamic cross-section의 구분이 핵심입니다.** 모든 비트 플립이 오류가 되지는 않습니다. 사용되지 않는 LUT의 업셋, 읽히기 전에 덮어써지는 레지스터의 업셋은 결과에 영향이 없습니다. **dynamic cross-section**은 실제 출력 오류로 이어진 것만 셉니다. → "비트 플립 발생률"과 "관측되는 시스템 오류율" 사이에는 워크로드 의존적인 큰 간극(**derating factor**)이 있습니다.

**SER이 커지는 세 가지 경로**
1. **소자 수**: FIT는 소자 수에 선형. FIT_overall = X × N. 개별 소자가 안전해도 10만 노드면 시스템 MTTF가 일 단위로 떨어집니다.
2. **고도·위도**: 위도 60°·40k ft에서 중성자 플럭스가 NYC 해수면 대비 **약 500배**. 동일 소자의 업셋 간격이 **75년 → 1.8개월**로 바뀝니다.
3. **미세화**: 로드맵 기준 데이터센터 시스템 MTTF가 수 분 수준까지 갈 수 있다는 전망 (전망치).
→ **명제: SRAM soft error는 "칩이 나빠져서" 문제가 되는 것이 아니라, 주로 "칩을 많이 쓰기 때문에" 문제가 됩니다.** 데이터센터·AI 클러스터 규모에서 SER이 재부상하는 구조적 이유입니다.

### 2-3. NAND — 리텐션 vs 내구성 트레이드오프의 정확한 구조

cai2017의 수명 정의가 이 절의 전부입니다.
> SSD 수명 = **최소 리텐션 보증을 지키면서** 수행 가능한 P/E 사이클 수 (cai2017.txt L132-136)

즉 **P/E 사이클 수와 리텐션 기간은 독립적인 두 스펙이 아니라 하나의 예산을 나눠 쓰는 관계**입니다. 요구 리텐션을 줄이면 더 많은 P/E 사이클을 허용할 수 있고, 그 반대도 성립합니다.

메커니즘: P/E 사이클을 반복하면 터널 산화막이 열화되어 전하 트래핑이 누적됩니다(cai2017.txt L1457, L1497). 트랩된 전하는 TAT(trap-assisted tunneling)를 강화해 **누설을 가속**합니다(L1817-1818). 결과적으로 **마모가 진행될수록 같은 리텐션 기간을 지키기 어려워집니다.** 컨트롤러가 P/E 사이클 수에 따라 refresh 주기를 연 1회에서 주 1회로 좁히는 것(L2485-2490)이 바로 이 의존성에 대한 대응입니다.

**"3,000 사이클"의 정확한 의미**: 이 수치는 "3,000회 쓰면 셀이 죽는다"가 아니라 **"3,000회 시점에서 RBER이 그 컨트롤러의 ECC 정정 한계를 넘는다"**입니다. 따라서 **ECC를 BCH에서 LDPC로 바꾸면 같은 셀의 사이클 수가 올라갑니다.** 내구성 수치는 셀 고유값이 아니라 **셀 + ECC + 리텐션 요구의 3자 함수**입니다.

### 2-4. NAND — read disturb / program disturb

**read disturb**: 어떤 워드라인을 읽으려면 같은 스트링의 나머지 워드라인에 pass voltage를 걸어 도통시켜야 합니다. 이 전압이 읽지 않는 셀에 **약한 프로그램 스트레스**로 작용해 문턱전압을 **위로** 밀어 올립니다. cai2017 실측(2,000 P/E 사이클 블록, 1회 vs 10K vs 100K disturb)에서 문턱전압 상승이 **ER·P1 상태(전하가 적은 상태)에 집중**됩니다(L1940-1943). 전하가 적은 셀일수록 터널 산화막에 걸리는 전계가 커서 터널링 전류가 강하기 때문입니다.
→ **비대칭성이 중요합니다. read disturb는 모든 셀을 균일하게 망가뜨리지 않고, 지운 상태(ER)에 가까운 셀부터 망가뜨립니다.**

**program disturb**: 같은 워드라인/비트라인을 공유하는 이웃 셀이 프로그램 전압의 영향을 받습니다. cai2017은 이를 cell-to-cell program interference로 다루며, **평면 미세화에서 심각했으나 3D의 큰 공정 치수에서는 문제가 되지 않아 제조사들이 one-shot programming으로 되돌아갔다**고 기술합니다(L3712-3715). 즉 **program disturb는 3D 전환으로 상당 부분 해소된 문제**입니다.

**셀 간 편차**: read disturb 취약도 자체가 공정 편차에 따라 셀마다 다릅니다. 취약한 셀은 더 빠르게 악화되고, 내성 있는 셀은 계속 내성을 유지합니다(L1953-1958). 즉 **최악 셀이 블록 수명을 결정**합니다.

### 2-5. NAND — 층수 증가가 신뢰성에 주는 영향

3D 적층은 신뢰성에 **단일 방향의 영향을 주지 않습니다.** 두 축으로 나눠야 합니다.

**축 1: 평면 치수 완화 (개선)**
층을 쌓아 밀도를 벌면 평면 치수를 되돌릴 수 있습니다. 15–19 nm → 50–54 nm (2017년 시점). 미세화가 원인이던 오류들이 함께 완화됩니다: read disturb 감소, program interference 감소, P/E 내구성 1자릿수 이상 증가.

**축 2: CT 셀 + z축 (악화)**
3D는 FG 대신 CT를 씁니다. CT는 고전압 내성이 좋지만, 전하가 **z 방향(수직)으로도 이동**할 수 있어 리텐션 누설이 커집니다. Luo 2018이 실측한 3가지는 모두 **z축 때문에 새로 생긴** 문제입니다:
1. **층간 공정 편차** — 채널 홀이 위에서 아래로 뚫리며 테이퍼가 생겨 층마다 셀 치수가 다릅니다. 상단 절반이 하단 절반보다 오류율이 낮고, 중간 층 RBER이 상단 대비 최대 6배(페이지·정규화 기준에 따라 21배).
2. **early retention loss** — 프로그램 후 약 3시간 안에 리텐션 오류율이 한 자릿수 급등한 뒤 완만해집니다. 갓 쓴 데이터가 가장 빨리 나빠지는 구간이 있습니다.
3. **retention interference** — **수직으로** 인접한 셀의 저장 상태가 대상 셀의 누설 속도를 바꿉니다. 인접 셀이 전하를 많이 담을수록 누설이 느려집니다.

→ **층수를 늘리는 것은 "같은 문제를 더 많이 만드는 것"이 아니라 "문제의 종류를 바꾸는 것"입니다.** 미세화형 오류(disturb·interference)에서 **구조형 오류(층간 편차·z축 누설)** 로 지배 요인이 이동합니다.
→ 실무적 함의: 층간 편차는 **정적이고 예측 가능**합니다(같은 칩의 서로 다른 블록에서도 일관되게 관측됨). 따라서 층별 읽기 기준전압 튜닝(LaVAR)이나 층 인터리빙 RAID(LI-RAID) 같은 **결정론적 보정**이 통합니다. 이는 무작위 오류에 대한 ECC와는 성격이 다른 대응입니다.

### 2-6. NAND — 필드 데이터가 뒤집은 통념 (Meza 2015)

**(a) 고장률은 쓰기량에 단조 증가하지 않습니다.**
전통적 bathtub 곡선(초기 고장 → 안정 → 마모)이 아니라, Facebook 데이터는 **early detection → early failure → useful life → wearout**의 4구간을 보입니다. 초기에 고장률이 **올랐다가 다시 내려갑니다.**
저자들의 가설: 초기에 취약 셀이 드러나며 정정 불가 오류를 내고(고장률 상승), 이 블록들이 예비 블록 풀로 리매핑되어 소진되면 **전체 오류율이 다시 내려갑니다**. 즉 초기 고장률 상승은 **결함의 발현이 아니라 결함의 색출 과정**입니다.
→ **함의: SSD의 "번인 기간" 데이터를 마모 데이터로 오해하면 수명 추정이 크게 틀립니다.**

**(b) 오류는 극단적으로 편중되어 있습니다.**
상위 10% SSD가 전체 정정 불가 오류의 80% 이상(일부 플랫폼 95% 이상). 1주차에 오류가 난 드라이브의 99.8%가 2주차에도 오류. 분포는 shape 0.3의 Weibull.
→ **함의: "평균 SSD"는 존재하지 않습니다.** 평균 UBER로 fleet을 설계하면 안 되고, **소수의 나쁜 드라이브를 조기에 골라내는 것**이 실질적 신뢰성 전략입니다.

**(c) 온도 효과는 스로틀링에 가려집니다.**
30–40°C에서는 온도-고장률이 증가 관계지만, 40°C 이상에서는 플랫폼이 세 갈래로 갈립니다. 원인은 컨트롤러 스로틀링(약 80°C부터)이 개입해 **고온 노출 자체를 줄여버리기** 때문입니다. 관측되는 온도-고장률 곡선은 **물리(Arrhenius)와 제어(스로틀링)의 합성**이며, 물리만 읽어내면 틀립니다.

### 2-7. HBM/DRAM — PPR의 soft와 hard

PPR은 **패키징 이후에 발견된 불량 row를 예비 row로 대체**하는 기능입니다. 웨이퍼 테스트 단계의 리페어가 아니라 **필드에서의 수리**라는 점이 핵심입니다.

**hPPR (hard)**: e-fuse를 끊어 **영구 대체**. 되돌릴 수 없습니다. Bank Group당 1개 row(DDR5 draft 기준). **tPGM 최소 1000 ms** — 1초 동안 REF 외의 명령을 받을 수 없으므로 **정상 서비스 중에는 사실상 불가**하고, 유지보수 창(재부팅·BIOS 단계)에서 수행하는 것이 전제입니다.

**sPPR (soft)**: 내부 레지스터에 대체 주소를 적어 **일시 대체**. **tPGMSPT 최소 50 µs**로 hPPR 대비 약 2만 배 빠릅니다. 대신 **전원이 끊기거나 RESET되면 사라집니다.**

**둘의 역할 분담**: sPPR은 **런타임 응급조치**입니다 — 오류가 나는 row를 즉시 격리해 서비스를 계속하고, 다음 유지보수 창에서 hPPR로 영구화합니다. 다만 초안 문서는 **sPPR도 hPPR 리소스 풀을 공유**한다고 기술합니다("hPPR 리소스가 소진된 bank group은 sPPR도 불가"). 즉 **sPPR은 hPPR의 예비 row를 빌려 쓰는 것**이며, 무한정 쓸 수 있는 임시방편이 아닙니다.

**안전장치**: 진입에 연속 4회 MRW의 guard key가 필요합니다. hPPR이 비가역이므로 사고성 진입을 막아야 하기 때문이고, 특히 **Command/Address 트레이닝 중** 의도치 않은 진입을 명시적으로 경계합니다. 다만 **잘못된 키를 넣어도 DRAM은 오류를 알려주지 않습니다** — 컨트롤러가 스스로 시퀀스 정확성을 보장해야 합니다.

**부작용**: sPPR 시퀀스 동안 refresh가 금지되므로, 수리에 걸리는 시간이 다른 row의 리텐션 예산을 잠식합니다. **리페어와 리프레시가 같은 시간 예산을 놓고 경쟁**합니다.

### 2-8. HBM — 적층 열의 구조 (thermrev 기반, 정성)

**(a) HBM은 열을 스스로 만드는 것보다 남의 열을 받는 것이 더 문제일 수 있습니다.**
thermrev는 HBM-GPU 모듈에서 **GPU로부터의 열 결합이 HBM 열 응력을 지배하는 요인이 될 수 있다**고 기술합니다. HBM 스택 내부 발열원은 base die와 memory PHY이지만, 인접 로직의 고밀도 핫스팟이 인터포저·패키지를 통해 전달되는 성분이 더 클 수 있습니다.

**(b) 가장 뜨거운 다이는 최상단이 아니라 중간입니다.**
직관적으로는 히트싱크에서 먼 최하단이나, 열원에 가까운 쪽이 뜨거울 것 같지만, thermrev의 Figure 2 캡션은 **중간 다이가 최고 접합 온도에 도달**한다고 명시합니다. 이유는 열이 위로 빠져나가려면 **여러 층의 마이크로범프 계면(TBR 지배)과 low-κ BEOL**을 통과해야 하고, 아래로 빠져나가려면 인터포저·기판을 지나야 하는데, **중간 다이는 양쪽 모두로 가는 경로가 길기 때문**입니다.
→ **함의: HBM 온도를 스택 상단 센서 하나로 대표시키면 최악점을 놓칩니다.**

**(c) 열 병목은 다이가 아니라 계면입니다.**
지배적 저항은 실리콘 자체가 아니라 **TIM, 마이크로범프 접합의 TBR(thermal boundary resistance), 다이 간 본딩층, HBM-인터포저 접합**입니다. → **하이브리드 본딩이 열적으로 유리하다는 주장의 근거가 여기 있습니다.** 마이크로범프 계면을 없애면 TBR 지배 저항이 사라집니다. (다만 thermrev에서 하이브리드 본딩의 정량적 열 개선치는 확인하지 못했습니다.)

**(d) 열-누설 양의 피드백**
온도 상승 → 누설 전류 증가 → 발열 증가 → 온도 상승. 이 루프가 핫스팟을 국소적으로 폭주시킬 수 있습니다. DRAM에서는 여기에 **리텐션 악화 → refresh 증가 → 전력 증가**라는 두 번째 루프가 겹칩니다.

**(e) 로직+HBM(2.5D)과 로직-on-로직(3-DHI)은 다른 문제입니다.**
thermrev는 두 구성을 명확히 구분합니다. 로직-on-로직은 **수직으로 정렬된 핫스팟들이 중첩**되는 것이 핵심 문제인 반면, 로직+HBM은 메모리 티어가 로직 옆에 배치되므로 문제의 형태가 다릅니다. HBM4에서 base die가 로직 공정 커스텀 실리콘으로 전환되면서 **HBM 스택이 로직-on-로직의 성격을 일부 갖게 되는 것**이 새로운 열 리스크 지점이지만, 이는 thermrev에서 직접 확인한 내용이 아닌 추론이므로 근거로 쓰지 마십시오.

| HBM 스택 내 최고온 다이 위치 | **중간(middle) 다이** (thermrev L206-208) | (대조 데이터 확보 실패) | **단일 출처.** "상단이 뜨겁다"/"하단이 뜨겁다" 어느 쪽도 근거 없이 쓰지 말 것. 정량 온도차는 확인 실패 |

## 5. 기존 소스 팩(v3)과의 충돌

**직접적인 수치 충돌: 없음.** v3 소스 팩(`RAM-source-pack.md`)은 밀도·대역폭·용량·공정 중심이고, 신뢰성 수치를 거의 담고 있지 않아 이번 조사와 겹치는 정량 항목이 없습니다.

**보완·주의가 필요한 접점 3건**

| v3 위치 | v3 서술 | 이번 조사의 관계 |
|---|---|---|
| v3 L51 "쓰기 내구성" 행 | SRAM·HBM·DRAM = **"무제한"**, HBF·NAND = **"제한"** | **충돌은 아니지만 오해 소지가 있습니다.** SRAM·DRAM은 **쓰기 마모(wear-out)** 가 없다는 의미로는 맞으나, 이번 조사가 보여주듯 **soft error(SRAM)** 와 **row 불량 → PPR 필요(DRAM)** 라는 별도의 신뢰성 제약이 존재합니다. "무제한"은 **쓰기 횟수 축에 한정된 표현**임을 각주로 명시할 것을 권합니다 |
| v3 L116 | "3nm GAA-FET SRAM의 self-heating 및 방사선 내성 연구 (SJSU/Sandia, 2026-07, T2)" | **이번 조사에서 원문을 확보하지 못했습니다.** v3의 이 항목은 이번 조사로 검증되지도 반박되지도 않았습니다. 별도 확보 필요 |
| v3 L301 | HBF의 "쓰기 내구성 정량 스펙 (P/E 사이클, DWPD 상당치)" 미확보로 표기 | **이번 조사도 확인 실패입니다.** 다만 참고 배경으로, cai2017 기준 평면 TLC ~1,000 P/E / 3D 전환 시 1자릿수 이상 개선이라는 **일반 NAND 근거**를 제공할 수 있습니다. **HBF 고유 스펙이 아니므로 HBF 수치로 전용하지 마십시오** |

**v3에 추가 가능한 신규 축**: v3의 5축 좌표(A1 지연 / A2 대역폭 / A3 용량 / A4 비용 / A5 결합도)에 **신뢰성**은 포함되어 있지 않습니다. 이번 조사 결과는 각 계층의 **실패 양식(failure mode)이 서로 다른 종류**임을 보여줍니다 — SRAM은 확률적 일시 오류(soft error), NAND는 결정론적 마모 + 구조적 편차, HBM/DRAM은 개별 소자 결함 + 열. "상위 계층일수록 신뢰성이 높다"는 단선적 정렬이 성립하지 않으므로, 신뢰성을 6번째 축으로 추가하려면 **단일 스칼라가 아니라 "지배적 실패 양식"이라는 범주형 속성**으로 다뤄야 합니다.

## 6. 집필 시 주의 (서술 규칙 제안)

### R1. **연도 병기는 선택이 아니라 필수입니다** (최우선 규칙)

이 절의 근거 자료 발표 연도는 다음과 같습니다. **본문에서 수치를 인용할 때마다 연도를 함께 쓰십시오.**

| 자료 | 발표 연도 | 2026년과의 간격 |
|---|---|---|
| fb_flash (Meza et al., Facebook) | **2015** (데이터 수집 ~2014-11) | **약 12년** |
| cai2017 (Cai et al.) | **2017** | **약 9년** |
| nand_retention (Luo et al.) | **2018** | **약 8년** |
| arm_n1 TRM | **2016–2019** | 약 7~10년 |
| arm_a78 TRM | **2018–2020** | 약 6~8년 |
| jesd79_5 (DDR5 draft) | Ballot 표기 **Q3'16 / Q1'17 / Q3'17** | 약 9~10년 |
| thermrev | 최근 리뷰로 추정 (**발행연도 확인 실패**) | 미상 |
| ssdsurvey | 본문에 2023년 사례 언급 (**발행연도 확인 실패**) | 미상 |

**금지 표현**: "현재 TLC NAND는 3,000 사이클을 견딘다", "SSD의 UBER는 10⁻⁹ 수준이다", "ARM 코어는 L2에 ECC를 쓴다"
**허용 표현**: "2017년 조사 기준 1x-nm 평면 MLC는 약 3,000 P/E 사이클이었다", "2015년 Facebook 필드 스터디에서 플랫폼별 UBER는 2.6×10⁻⁹~5.1×10⁻¹¹였다", "2020년 Cortex-A78 TRM 기준 L2 캐시 data RAM은 64비트당 ECC 8비트의 SECDED이다"

### R2. **cai2017의 P/E 수치를 2026년 3D NAND에 적용하지 마십시오**

3,000(MLC) / 1,000(TLC)은 **2017년 시점 1x-nm 평면(2D) NAND** 값입니다. 같은 논문이 3D 전환으로 내구성이 **1자릿수 이상 증가**했다고 명시합니다. 그런데 **개선 후의 절대값은 어느 자료에도 없습니다.** 따라서:
- ❌ "TLC NAND는 1,000 사이클" → 현행 제품에 대해 **명백히 틀린 서술**
- ❌ "3D TLC는 10,000 사이클" → **1자릿수 개선을 임의로 곱한 근거 없는 값**
- ⭕ "2017년 기준 1x-nm 평면 TLC는 약 1,000 P/E 사이클이었고, 같은 자료는 3D 전환으로 공정 치수가 완화되며 내구성이 1자릿수 이상 개선되었다고 보고한다. **개선 후 절대값은 이 자료에 제시되지 않았다**"

### R3. **P/E 사이클은 셀의 물리 상수가 아닙니다**

"3,000 사이클"은 **RBER이 그 컨트롤러의 ECC 정정 한계를 넘는 지점**입니다. 같은 셀도 BCH를 LDPC로 바꾸면 사이클 수가 올라가고, 요구 리텐션을 줄이면 또 올라갑니다.
→ 내구성 수치를 쓸 때는 **"셀 + ECC + 리텐션 요구"의 3자 함수**임을 최소 1회 서술하십시오. 그렇지 않으면 독자가 P/E 사이클을 소자의 고정 스펙으로 오해합니다.

### R4. **"리텐션과 내구성의 트레이드오프"를 두 개의 독립 스펙처럼 쓰지 마십시오**

cai2017의 정의를 그대로 쓰는 것이 가장 안전합니다: **SSD 수명 = 최소 리텐션 보증을 지키면서 수행 가능한 P/E 사이클 수.** 하나의 예산을 나눠 쓰는 관계이지, "내구성도 좋고 리텐션도 좋아야 한다"는 병렬 요구가 아닙니다.

### R5. **3D 적층의 신뢰성 영향을 한 방향으로 쓰지 마십시오**

"층을 쌓으면 신뢰성이 나빠진다"도 "좋아진다"도 모두 틀립니다. 정확한 서술은 **"지배적 실패 양식이 바뀐다"**입니다.
- 개선: read disturb ↓, program interference ↓, P/E 내구성 ↑ (평면 치수 완화 덕)
- 악화: 리텐션 누설 ↑ (CT 셀 + z축 이동), **층간 공정 편차**(신규), **early retention loss**(신규), **retention interference**(신규)
특히 뒤의 3가지는 **평면 NAND에 존재하지 않던 새로운 오류원**이며 Luo et al. 2018이 실측으로 최초 특성화했다는 점을 밝히십시오.

### R6. **층간 편차 배수는 조건을 반드시 병기하십시오**

같은 논문에 **6배**와 **21배**가 모두 나옵니다. 조건이 다릅니다.
- "6배" = 중간 층 RBER / 상단 층 RBER (논문 서두 요약)
- "21배" = 정규화 layer 55의 **MSB 페이지** RBER / layer 0 (본문 최대치)
둘 중 하나만 조건 없이 쓰면 다른 자료와 대조할 때 즉시 모순처럼 보입니다.

### R7. **ARM TRM 값을 "ARM 아키텍처의 규정"으로 일반화하지 마십시오**

TRM은 **특정 코어의 특정 리비전**을 기술합니다. A78과 N1은 태그 폭(31 vs 39 bit, 34 vs 42 bit)이 다르고, **A78은 L1 보호를 "optional"로 기술**합니다. 실리콘 구현체가 이 옵션을 켰는지는 TRM으로 알 수 없습니다.
- ❌ "ARM 코어는 L1 태그를 39비트 granule 패리티로 보호한다"
- ⭕ "Neoverse N1 TRM(2019) 기준 L1 명령 캐시 태그는 39비트 granule에 패리티 1비트로 보호된다. Cortex-A78(2020)은 같은 항목이 31비트이며, L1 보호를 optional 파라미터로 기술한다"

### R8. **"L1은 패리티, L2/L3는 ECC"라는 통설을 그대로 쓰지 마십시오 — 절반만 맞습니다**

ARM TRM이 실제로 보여주는 것은 **명령/데이터의 구분**이지 계층 깊이의 구분이 아닙니다.
- L1 **명령** 캐시 = 패리티 + 무효화·재fetch (clean read-only이므로 정정 불필요)
- L1 **데이터** 캐시 = **SECDED** (dirty 유일본을 담으므로 정정 필수)
- L2 = SECDED
즉 **"L1은 패리티"는 명령 캐시에만 해당합니다.** L1 데이터 캐시는 ECC입니다. 이 구분을 하지 않는 자료가 많으므로 차별화 지점이 됩니다.
또한 **L3에 대한 근거는 확보하지 못했습니다** — 이 TRM들은 L0/L1/L2와 MMU까지만 다룹니다. L3를 언급하려면 별도 출처가 필요합니다.

### R9. **보호하지 않는 RAM이 있다는 사실을 빠뜨리지 마십시오**

BTB·GHB·BIM·PHT·L2 victim은 보호가 **없습니다(None)**. 아키텍처적으로 가시적인 상태가 아니면 보호하지 않는 것이 원칙입니다. "캐시는 ECC로 보호된다"고 뭉뚱그리면 **비용-보호 설계 판단**이라는 가장 흥미로운 부분이 사라집니다.

### R10. **SER은 소자 스펙이 아니라 환경과의 곱입니다**

FIT는 static cross-section × flux입니다. 같은 소자가 NYC 해수면에서 **75년/업셋**, 40k ft·위도 60°에서 **1.8개월/업셋**입니다. 그리고 **소자 수에 선형**입니다.
→ **"미세화 때문에 SRAM SER이 문제가 된다"고 단정하지 마십시오.** 로컬 자료가 뒷받침하는 것은 **규모(N)와 환경(flux)** 효과이며, **공정 노드별 SER 추이 데이터는 확보하지 못했습니다**(4-1절). 미세화 추이를 서술하려면 별도 출처가 필요하고, 없다면 규모·환경 효과만 쓰십시오.

### R11. **비트 플립 발생률 ≠ 관측되는 시스템 오류율**

static cross-section(업셋)과 dynamic cross-section(실제 출력 오류)은 다릅니다. 읽히기 전에 덮어써지는 값의 업셋은 오류가 되지 않습니다. **derating**을 언급하지 않고 업셋률을 시스템 오류율처럼 제시하면 과대평가입니다.

### R12. **jesd79_5.txt 인용 시 "위원회 초안"임을 반드시 표기하십시오**

이 파일은 **DDR5 Full Spec Draft Rev0.1 (JC42.3 회람본)**입니다. 최종 비준본이 아닙니다. 근거가 되는 실물 증거: 본문에 **"sPPR은 Bank Group당 TBD개 Row를 수리한다"**처럼 **TBD가 그대로 남아 있습니다.** 각 절에 `Q3'16 Ballot #1830.51` 식의 **볼로트 번호**가 붙어 있는 것도 초안의 표식입니다.
→ 표기 예: "JESD79-5 **DDR5 Full Spec Draft Rev0.1**(위원회 회람본, Q3'17 Ballot #1830.51) 기준. **최종 비준 사양과 다를 수 있음**"

### R13. **PPR을 HBM 기능으로 서술하지 마십시오 — 확보한 근거는 DDR5입니다**

이번 조사에서 확보한 hPPR/sPPR 사양은 **전부 DDR5(JESD79-5 초안)** 것입니다. **HBM 규격서(JESD235 계열)는 로컬에 없습니다.** HBM도 PPR을 지원한다는 것은 업계에 알려진 사실이지만, **본 조사의 근거로는 뒷받침되지 않습니다.**
- ❌ "HBM은 hPPR로 bank group당 row 1개를 수리한다"
- ⭕ "DDR5(JESD79-5 초안) 기준 hPPR은 bank group당 row 1개를 e-fuse로 영구 수리하며 tPGM 최소 1000 ms가 필요하다. **HBM의 PPR 사양은 본 조사에서 확인하지 못했다**"

### R14. **hPPR의 1초는 서술의 핵심 포인트입니다**

tPGM(min) = **1000 ms**. 그 동안 REF 외의 명령을 받을 수 없습니다. sPPR은 **50 µs**입니다. **약 2만 배 차이**입니다. 이 격차가 "왜 두 종류가 필요한가"를 설명합니다 — sPPR은 런타임 응급조치, hPPR은 유지보수 창 작업입니다.
단, **sPPR은 hPPR의 예비 자원을 공유합니다**("hPPR 리소스가 소진된 bank group은 sPPR도 불가"). sPPR을 "무한정 쓸 수 있는 임시방편"으로 묘사하지 마십시오.

### R15. **HBM 다이 온도차에 숫자를 쓰지 마십시오 — 확보하지 못했습니다**

이번 조사의 가장 큰 공백입니다. mdpi_hbm.pdf·mdpi_tsv.pdf가 **모두 Access Denied로 다운로드 실패**했습니다(4-0절). thermrev.txt에 나오는 **±2–3°C, ±3–10°C는 측정 장비의 불확실도**이지 다이 간 온도차가 아닙니다. 이것을 온도 구배로 인용하는 것은 **명백한 오독**입니다.
쓸 수 있는 것은 **정성 서술 하나뿐**입니다: "열 저항이 큰 TIM·마이크로범프 계면·low-κ BEOL이 겹쳐 **중간 다이가 최고 접합 온도에 도달**한다 (thermrev, T2, 단일 출처)".
→ "상단과 하단이 N도 차이난다"는 형태의 문장을 쓰려면 **새 출처를 확보한 뒤**에 하십시오.

### R16. **HBM 열의 원인을 HBM 자신으로만 돌리지 마십시오**

thermrev는 HBM-GPU 모듈에서 **GPU로부터의 열 결합이 HBM 열 응력을 지배하는 요인이 될 수 있다**고 기술합니다. HBM이 뜨거운 이유의 상당 부분이 **이웃 로직 때문**일 수 있습니다. 또한 열 병목은 실리콘이 아니라 **계면(TIM, 마이크로범프 TBR, 본딩층)**입니다. 이것이 하이브리드 본딩의 열적 이점 논리의 출발점입니다 — 다만 **정량 개선치는 확인 실패**입니다.

### R17. **TSV 리던던시에 대해서는 아무 수치도 쓰지 마십시오**

mdpi_tsv.pdf 접근 차단으로 **TSV 결함률·리던던시 본수·리페어 방식에 대한 근거를 전혀 확보하지 못했습니다.** thermrev는 TSV를 열 경로로만 다룹니다. 이 항목은 **완전한 공백**으로 남겨두거나, 별도 출처를 확보한 뒤 채우십시오.

### R18. **Facebook 필드 데이터의 두 가지 반직관적 결과를 살리십시오**

(a) **고장률이 쓰기량에 단조 증가하지 않습니다.** early detection 구간에서 올랐다가 내려갑니다. 원인은 취약 블록이 색출되어 예비 풀로 리매핑되는 과정입니다. → SSD 초기 데이터를 마모 데이터로 읽으면 수명 추정이 틀립니다.
(b) **오류는 극단적으로 편중되어 있습니다.** 상위 10% 드라이브가 오류의 80~95%를 냅니다. 1주차 오류 드라이브의 99.8%가 2주차에도 오류를 냅니다. → **"평균 SSD"로 fleet을 설계하면 안 됩니다.**
(c) 온도-고장률은 **30–40°C에서만 증가 관계**이고, 40°C 이상에서는 스로틀링이 개입해 플랫폼별로 갈립니다. "고온이면 SSD가 더 고장난다"는 단순 서술은 이 논문이 오히려 반박하는 쪽에 가깝습니다.

### R19. **fb_flash의 UBER를 "SSD의 신뢰성"으로 일반화하지 마십시오**

이 값들은 **2014년 Facebook 데이터센터의 커스텀 PCIe 플래시 카드 6개 플랫폼**에서 나온 것입니다. 소비자용 SSD도, 2026년 제품도 아닙니다. 플랫폼 간 편차 자체가 **50배 이상**(2.6×10⁻⁹ vs 5.1×10⁻¹¹)이므로, **단일 대푯값으로 쓰는 순간 의미가 사라집니다.**

### R20. **계층별 신뢰성을 "상위일수록 안전하다"로 정렬하지 마십시오**

v3의 5축 논의와 같은 문제입니다. 신뢰성은 단일 스칼라로 정렬되지 않습니다. 각 계층은 **다른 종류의 실패**를 합니다.
- **SRAM**: 확률적·일시적 (soft error). 마모 없음. 대응 = 패리티/ECC + 재fetch. **환경과 규모의 함수**
- **NAND**: 결정론적·누적적 (마모) + 구조적 편차 (층간). 대응 = LDPC + read retry + refresh + 층별 보정
- **HBM/DRAM**: 개별 소자 결함 (row 불량) + 열. 대응 = PPR(soft/hard) + 냉각·스로틀링
→ **서술 원칙: "얼마나 신뢰할 수 있나"가 아니라 "어떻게 실패하고 무엇으로 막나"로 구성하십시오.** 이것이 계층 비교의 실질입니다.

본 문서에서 `단일 출처`로 표기한 값들(10만 노드 FPGA MTTF 0.5~11일, 3D TLC erase 표준편차 2.7 ms, 스로틀링 개시 80°C, early detection 구간 차이 81.7%, layer 55 MSB 21배, HBM 중간 다이 최고온)은 **교차 검증되지 않았습니다.** 본문에서 강조 수치로 쓰려면 표기하거나 추가 출처를 확보하십시오.
