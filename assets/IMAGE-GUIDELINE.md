> **최종 검증: 2026-07-29**
> 이 모음집의 이미지 33건은 전부 **SVG 코드로 직접 작성**합니다. 확산 모델(AI 이미지 생성)을 쓰지 않습니다.
> 건별 제작 사양은 [IMAGE-MANIFEST.md](IMAGE-MANIFEST.md)에 있습니다.

## 왜 SVG인가

이 모음집에는 그림의 수치가 본문과 **글자 단위로 일치**해야 한다는 규약이 있습니다. 확산 모델은 `13.75 ns`, `0.087 Gb/mm²/층`, `매몰 워드라인 (Buried WL)` 같은 라벨을 정확히 렌더링하지 못하고, "지지대의 개구를 통해서만 식각액이 들어간다"나 "리텐션 분포가 64 ms에서 좌측 절단된다" 같은 구조 관계를 보장하지 못합니다. 로그 스케일 막대 4건(#21·#27·#28·#32)은 생성이 아니라 계산으로 그려야 하는 정량 그래프입니다.

SVG는 라벨이 정확하고, 저장소에 텍스트로 들어가 diff가 남으며, 수정이 쉽고, 다크·라이트 대응을 CSS로 처리할 수 있습니다.

## 1. 시각 언어

### 1-1. 플랫 벡터만

단색 면과 균일 두께 선으로만 구성합니다.

**금지**: 그라데이션(`<linearGradient>`, `<radialGradient>`), 드롭섀도(`filter`), 광택·베벨, 3D 사시도·원근, 아이소메트릭 뷰, 텍스처·노이즈, 반사, 불투명도를 이용한 깊이 표현.

예외 하나 - **불투명도는 "가려짐"을 표현할 때만** 씁니다(예: 몰드 산화막 뒤에 있는 하부전극). 미감을 위해 쓰지 않습니다.

### 1-2. 순수 구조

그리는 것은 구조와 관계뿐입니다.

**금지**: 아이콘·픽토그램, 이모지, 로고, 말풍선, 배경 패턴·격자, 프레임 장식, 인물·손, 장식용 화살표, `Fig.` 머리글, 워터마크, 범례 상자의 장식 테두리, 둥근 그림자 카드.

### 1-3. 그림은 설명하지 않는다

설명은 본문과 캡션이 합니다. 그림 안에는 **부품 이름과 수치만** 들어갑니다.

- 나쁨: `이 지점에서 붕괴가 일어납니다`
- 좋음: `모세관력` + 해당 지점을 가리키는 지시선

문장형 주석, 결론 문구, 감탄 표현을 넣지 마십시오.

## 2. 색

### 2-1. 팔레트 (고정)

배경은 **투명**입니다. 아래 값은 라이트·다크 양쪽에서 읽히도록 중간 명도로 골랐습니다. 적록·청황 색각 이상에서 구분되는 Okabe–Ito 계열입니다.

| 역할 | HEX | 용도 |
|---|---|---|
| **SRAM** | `#0072B2` | 계층 고정색 |
| **DRAM** | `#009E73` | 계층 고정색 |
| **HBM** | `#56B4E9` | 계층 고정색 |
| **HBF** | `#CC79A7` | 계층 고정색 |
| **NAND** | `#E69F00` | 계층 고정색 |
| **강조** | `#D55E00` | 병목·결함·핵심 지점 |
| **구조선** | `#1F2328` (라이트) / `#E6EDF3` (다크) | 주 윤곽선, 라벨 |
| **보조선** | `#8B949E` | 치수선, 지시선, 축, 격자 |

**계층 색은 모음집 전체에서 고정**입니다. 같은 계층이 여러 그림에 나오면 항상 같은 색이어야 비교가 성립합니다.

**한 그림당 의미색 최대 4 + 중립 2**를 넘지 않습니다.

**예외 하나** - 다섯 계층 전체가 주제인 그림(#1, #20)은 계층 고정색 5종을 전부 씁니다. 대신 **강조색을 쓰지 않고** 강조를 해칭·점선·기하로만 표현해 의미색을 5로 묶습니다. 계층 비교가 목적인 그림에서 계층 하나를 색 없이 두는 것이 더 큰 손실이기 때문입니다.

### 2-2. 강조색과 NAND색의 충돌 방지

`#D55E00`(강조)과 `#E69F00`(NAND)은 색각 이상에서 혼동될 수 있습니다. 따라서 **강조 요소에는 색 외에 반드시 해칭 또는 점선 테두리를 함께** 씁니다. 색만으로 강조를 표현하지 마십시오.

### 2-3. 색만으로 정보를 전달하지 않는다

흑백 인쇄와 색각 이상에서도 읽히도록, 색으로 구분한 것은 **패턴 또는 라벨을 병기**합니다. 범례에만 의존하는 색 구분을 만들지 마십시오.

### 2-4. 다크·라이트 대응

SVG 파일 안에 CSS 변수와 미디어 쿼리를 넣습니다.

```svg
<style>
  :root {
    --stroke: #1F2328;
    --hint:   #8B949E;
  }
  @media (prefers-color-scheme: dark) {
    :root { --stroke: #E6EDF3; }
  }
  .s { stroke: var(--stroke); fill: none; stroke-width: 2; }
  .h { stroke: var(--hint);   fill: none; stroke-width: 1; }
  text { fill: var(--stroke); font-family: system-ui, sans-serif; }
</style>
```

계층색 6종은 두 모드에서 모두 읽히므로 고정값으로 둡니다. **구조선과 텍스트만** 모드에 따라 뒤집습니다.

## 3. 선과 형태

- 선 두께는 **2단계만** - 구조선 `2`, 보조선 `1`
- 화살표는 한 형태로 통일. **물질·데이터 흐름은 실선, 논리 관계·대응은 점선**
- 해칭은 **재료 구분과 구간 구분에만**. 구간 구분은 같은 계층색 안에서 부분을 나눌 때만 씁니다(예: #29 누적 막대의 CL / tRCD / tRP). 강조에는 쓰지 않음(2-2 예외)
- 모서리는 직각 또는 `rx="2"` 이하
- 파선 패턴은 `stroke-dasharray="4 3"` 하나로 통일

## 4. 텍스트

- 한글 + 영문 약어 병기 - `매몰 워드라인 (Buried WL)`, `관통 실리콘 비아 (TSV)`
- 폰트 1종(`system-ui, sans-serif`), 크기 **3단계만** - 그룹 라벨 `14`, 요소 라벨 `12`, 수치·단위 `11`
- **수치는 본문과 글자 단위로 일치.** 임의 반올림 금지, 단위 반드시 병기
- **그림 안에 제목과 캡션을 넣지 않습니다.** 캡션은 마크다운 이탤릭 줄이 담당합니다. 그림에 넣으면 본문 갱신 시 두 곳이 어긋납니다
- 텍스트는 `<text>` 요소로. **아웃라인 변환 금지**(검색·접근성·수정 가능성)

## 5. 스케일

- 로그 스케일이 필요한 그림(#21·#27·#28·#32)은 **축에 명시**합니다. 선형으로 그리면 논지가 사라집니다
- **동일 스케일** - #8·#10(HBM / HBF 스택). 두 스택이 같은 캔버스에 들어가므로 px 단위를 공유합니다. 공유 단위는 매니페스트 5-1절에 확정되어 있습니다
- **동일 축척 표기** - #14·#24(NAND 채널 홀 / DRAM 커패시터). 깊이가 6–10 µm 대 약 1 µm로 한 자릿수 차이라 같은 캔버스에 실비율로 담을 수 없습니다. 대신 **두 그림에 같은 단위의 스케일 바**를 넣어 수치로 비교할 수 있게 합니다
- **동일 스타일** - #18·#24(식각 중 결함 / dip-out 후 결함). 결함 표기 문법(강조 해칭, 기준선 파선, 깊이 축 처리)이 같아야 "식각 중"과 "제거 후"의 대비가 성립합니다
- 종횡비를 과장하지 않습니다. 100:1은 100:1로 보이게 하고, 지면상 불가하면 **절단 표시(break mark)**를 넣어 축약했음을 밝힙니다. 단 **#24는 세장비 자체가 논지이므로 절단 없이 실비율**로 그립니다

## 6. 불확실성의 시각화

이 모음집은 확정 사실과 미확정을 문장 단위로 구분합니다. 그림도 같아야 합니다. **도해는 확정된 사실처럼 보이는 힘이 강해서 텍스트보다 더 조심해야 합니다.**

## 7. 종류별 레이아웃 문법

6종은 배치 규칙이 각각 다릅니다. 이 규칙을 고정해야 33건이 한 세트로 보입니다.

| 종류 | 배치 | 규칙 |
|---|---|---|
| **셀 구조도** | 회로도 관례 | 표준 회로 기호. WL 수평·BL 수직, 전원 위·접지 아래 |
| **단면도** | 수직 단면 | 기판을 아래, 적층은 위로. 수직 축이 공정 순서 또는 물리 높이 |
| **구조도** | 물리 배치 | 실제 상대 위치 유지. 거리에 의미가 있으면 스케일 표시 |
| **비교도** | 좌우 2열 또는 누적 막대 | 비교 대상을 **같은 행에 정렬**. 대조 축을 축 라벨로 명시 |
| **흐름도** | 좌→우 또는 위→아래 단일 방향 | 분기·루프는 명시적. 단계 상자 크기 균일 |
| **개념도** | 관계 중심 | 물리 배치 아님. 화살표 수렴·발산으로 관계 표현 |

## 8. 산출 형식

- SVG, `viewBox` 고정, 폭 높이 속성은 두지 않음(반응형)
- 파일명 `<문서번호>-<일련번호>-<영문-슬러그>.svg` (예: `06-04-capacitor-mold-removal.svg`)
- `<title>`과 `<desc>`에 캡션과 요약을 넣어 스크린리더 대응
- 스크립트·외부 폰트·외부 이미지 참조 금지

### 8-1. 표준 프리앰블 (전 파일 공통, 그대로 복사)

33개 파일이 한 세트로 보이려면 스타일 정의가 동일해야 합니다. 아래 블록을 **문자 그대로 복사**하고 `viewBox`·`<title>`·`<desc>`만 바꾸십시오. 클래스를 새로 만들지 마십시오.

```svg
<svg viewBox="0 0 720 420" xmlns="http://www.w3.org/2000/svg" role="img" aria-labelledby="ttl dsc">
<title id="ttl">여기에 캡션 본문</title>
<desc id="dsc">여기에 한 문장 요약. 출처 한정(특허 실시례·계산값·벤더 전언)이 있으면 여기에 적습니다.</desc>
<style>
  :root{ --stroke:#1F2328; --hint:#8B949E; }
  @media (prefers-color-scheme:dark){ :root{ --stroke:#E6EDF3; } }
  .s{ stroke:var(--stroke); fill:none; stroke-width:2; stroke-linejoin:round; stroke-linecap:round; }
  .h{ stroke:var(--hint); fill:none; stroke-width:1; }
  .d{ stroke-dasharray:4 3; }
  text{ fill:var(--stroke); font-family:system-ui,-apple-system,"Segoe UI",sans-serif; }
  .t14{ font-size:14px; } .t12{ font-size:12px; } .t11{ font-size:11px; }
  .mid{ text-anchor:middle; } .end{ text-anchor:end; }
  .f-sram{ fill:#0072B2; } .f-dram{ fill:#009E73; } .f-hbm{ fill:#56B4E9; }
  .f-hbf{ fill:#CC79A7; }  .f-nand{ fill:#E69F00; } .f-emph{ fill:#D55E00; }
  .k-sram{ stroke:#0072B2; } .k-dram{ stroke:#009E73; } .k-hbm{ stroke:#56B4E9; }
  .k-hbf{ stroke:#CC79A7; }  .k-nand{ stroke:#E69F00; } .k-emph{ stroke:#D55E00; }
</style>
<defs>
  <marker id="ar" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse">
    <path d="M0,0 L10,5 L0,10 Z" fill="var(--stroke)"/>
  </marker>
  <pattern id="hatch" width="6" height="6" patternUnits="userSpaceOnUse" patternTransform="rotate(45)">
    <line x1="0" y1="0" x2="0" y2="6" stroke="var(--stroke)" stroke-width="1"/>
  </pattern>
  <pattern id="dots" width="6" height="6" patternUnits="userSpaceOnUse">
    <circle cx="3" cy="3" r="1" fill="var(--hint)"/>
  </pattern>
</defs>
```

**사용 규칙**

- 구조선은 `class="s"`, 보조선·치수선·축은 `class="h"`, 파선은 `.d`를 덧붙입니다
- 면 색은 `f-*`, 선 색은 `k-*`. 클래스 밖의 색을 직접 쓰지 마십시오
- 계층색 면은 `fill-opacity="0.15"`로 깔고 같은 색 테두리(`k-*`)를 얹어, 라이트·다크 양쪽에서 라벨이 읽히게 합니다
- 화살표는 `marker-end="url(#ar)"`
- 해칭은 `fill="url(#hatch)"`, 몰드·희생층 같은 제거 대상은 `fill="url(#dots)"`
- 폰트 크기는 `t14`(그룹 라벨) / `t12`(요소 라벨) / `t11`(수치·단위)만 씁니다
- **`<style>`과 `<defs>`에 항목을 추가하지 마십시오.** 부족하면 기하로 해결합니다

### 8-2. 캔버스 규격

| 용도 | viewBox |
|---|---|
| 기본 | `0 0 720 420` |
| 좌우 2패널 비교 | `0 0 720 400` |
| 5열 이상 격자 | `0 0 960 480` |
| 세로로 긴 단면 | `0 0 560 520` |

같은 비교쌍은 반드시 같은 규격을 씁니다.

| **검증** | 본문의 어느 수치·서술과 일치해야 하는가 |

## 10. 치환 절차

1. 생성 파일을 `assets/`에 둡니다
2. 본문의 플레이스홀더 줄을 `![캡션](assets/파일명.svg)`로 치환합니다. **아래 이탤릭 캡션 줄은 그대로 둡니다**
3. 매니페스트의 `파일명`·`상태` 열을 갱신합니다. **플레이스홀더 원문 문자열은 지우지 마십시오** - 재생성에 필요합니다
4. 수치가 들어간 이미지라면 [SOURCES.md](../SOURCES.md) 갱신 이력에 한 줄 남깁니다

## 11. 예외 - 저장소 썸네일

`assets/thumbnail.svg` 한 건은 **도해가 아니라 저장소 식별 자산**입니다. [README](../README.md) 상단에 놓이고, 본문의 어떤 서술도 뒷받침하지 않으며 수치·라벨·배지를 담지 않습니다. 성격이 달라 아래 다섯 가지를 의도적으로 어깁니다. **다른 파일에는 이 예외를 적용하지 마십시오.** 규약 검사를 돌릴 때도 이 파일은 대상에서 뺍니다.

| 어긴 규칙 | 내용 | 이유 |
|---|---|---|
| 1-1 불투명도 | 다이마다 `fill-opacity`를 세 단계(0.35 / 0.52 / 0.72)로 바꿔 명암대를 만듭니다 | 회절의 명도 변화는 웨이퍼를 알아보게 하는 1차 단서입니다. 가려짐 표현이 아니라 대상 자체의 성질입니다 |
| 4 그림 안 제목 | `RAM - Revealing Anatomy of Memory` 한 줄이 그림 안에 있습니다 | 썸네일은 단독으로 노출되므로 마크다운 캡션이 따라붙지 않습니다 |
| 4 폰트 3단계 | `.t32` 한 종을 더 씁니다 | 위와 같은 이유. 14px 제목은 썸네일에서 읽히지 않습니다 |
| 8-1 프리앰블 | `<style>`에 `.t32`를, `<defs>`에 `clipPath` 하나를 추가했습니다 | 다이 필드를 원형으로 자르는 것은 기하로 대체할 수 없습니다 |
| 8-2 캔버스 | `0 0 960 720` (4:3). 규격 표에 없습니다 | 썸네일 용도의 가로형 비율입니다 |

지킨 것은 지켰습니다.

- **팔레트 6종 밖의 색을 쓰지 않았습니다.** 회절색은 박막 간섭의 색 순환(마젠타 → 청 → 시안 → 녹 → 황 → 적)에 계층 고정색을 그대로 대응시켜 만들었습니다. `#CC79A7` → `#0072B2` → `#56B4E9` → `#009E73` → `#E69F00` → `#D55E00` 순서입니다
- 그라데이션·필터·3D·원근·텍스처가 없습니다. 색은 다이 단위 단색 면입니다
- 구조선과 텍스트만 다크·라이트에 따라 뒤집힙니다
- 참고 사진(`_internal/웨이퍼-참고.jpg`)을 트레이스하지 않았습니다. 가져온 것은 **원판·정사각 다이 격자·스크라이브 레인·엣지 배제 고리·노치**라는 구조뿐이며, 사진의 시점(사시)·조명·다이 수·색 배치를 재현하지 않았습니다. 다이 177개는 격자 계산의 결과이지 실제 제품의 다이 수가 아닙니다
